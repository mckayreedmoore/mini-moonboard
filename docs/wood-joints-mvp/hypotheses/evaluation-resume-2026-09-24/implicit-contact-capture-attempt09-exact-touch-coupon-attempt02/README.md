contact-capture patch. It uses the two-body C3D10 exact-touch deck, its exact
pair/face rosters, five open/touch/compress/touch/reopen states, and a pinned
unmodified upstream reference output. It does not use current candidate
geometry, loads, or materials and cannot accept any of the 47 criteria.

The owner authorized parent-owned native method checks after review of the

## Frozen checks

The reader validates run/input/build provenance, the exact source-face census,
every generated capture record and tie/state join, accepted iteration links,
zero overflow/error, and the complete terminal footer. The verifier requires
all five accepted total times, the compression slave resultant and contact
spring energy against their analytical answers, and byte-for-byte parity of
`.cvg`, `.dat`, `.frd`, and `.sta` with the pinned unmodified 2.23 baseline.

The standard-output baseline is also pinned to the independently reviewed
[exact-touch work known-answer fixture](../contact-penalty-touch-work-known-answer-attempt01/RESULTS.md).
That fixture checked signed top-reaction work, body `ELSE`, contact `CELS`,
pair `CF`/`CFN`/`CFS`, and section outputs for the same five-step deck. Its
review and native records are re-hashed before this coupon can start. The
attempt09 capture coupon itself only validates the capture instrumentation and
standard-output invariance; the prior fixture's acceptance remains limited to
that two-body method fixture.

The capture intentionally excludes the pre-loop seed scan. Runtime face-span
conservation does not prove geometric search completeness. Unmapped or
excluded-point forces and nodal correction work remain unbounded. This coupon
establishes no general contact-history law, wood-joint resistance, candidate
capacity, criterion pass, or whole-frame response.

## Run controls

The input freeze pins the attempt09 source archive and patch, build manifest,
exact image ID and binary hash, upstream manual, expected reader bindings,
known-answer outputs, owner instructions, reviews, and single-case limits.
Docker is configured with no network or pull, one CPU, 1 GiB memory/swap, a
60-second timeout, and bounded capture/stdout/stderr/total output. The runner
refuses to launch unless the parent readiness, authorization, and consumed
ledger reservation match this exact freeze and run ID. It refuses to overwrite
any output.

After readiness and the ledger reservation are finalized, the coordinator runs
once from the repository root:

```sh
python3 docs/wood-joints-mvp/hypotheses/evaluation-resume-2026-09-24/implicit-contact-capture-attempt09-exact-touch-coupon-attempt02/run.py
python3 docs/wood-joints-mvp/hypotheses/evaluation-resume-2026-09-24/implicit-contact-capture-attempt09-exact-touch-coupon-attempt02/verify.py
```

A failed or interrupted launch consumes this run ID; a retry requires a new
freeze and run ID. A passing result qualifies the capture method only. It does
not authorize a current-joint case or change an engineering criterion.
