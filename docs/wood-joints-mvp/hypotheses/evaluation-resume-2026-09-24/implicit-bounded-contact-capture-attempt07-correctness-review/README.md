**Disposition: REVISE.** The archive and predecessor pins are exact, patch replay is additions-only, and the offline suite passes. Three correctness gaps remain in cutback linking, empty state joins, and independent reader validation.

1. **High — A valid accepted retry after cutback is marked invalid.** At [capture-sink.inc:428](../implicit-bounded-contact-capture-attempt07/capture-sink.inc:428), generation begin stores the attempt as `*icutb + 1`. The post-checkconvergence hook at [capture-sink.inc:618](../implicit-bounded-contact-capture-attempt07/capture-sink.inc:618) accepts only the captured attempt or its successor. In the pinned CalculiX 2.23 [`checkconvergence.c`](../implicit-bounded-contact-capture-attempt07/build/context/source.tar.bz2), a successful increment sets `*icntrl = 1` and resets `*icutb = 0` at lines 348–350; the cutback branches increment `*icutb` at lines 701–702 and 820–821. Thus, a retry that starts with `icutb == 1` is captured as attempt 2, then successful convergence reports `attempt_after == 1`. The sink rejects that transition because 1 is neither 2 nor 3, sets the run error, and prevents a valid capture from passing.

   A temporary standalone sink-harness probe exercised that exact post-convergence state. It emitted link fields `[captured attempt, captured iteration, attempt_after, icntrl, accepted] = [2, 1, 1, 1, 1]` but ended with `RUN_END [overflow, error, complete] = [0, 1, 0]`. The existing `cutback-link` test covers a cutback from attempt 1 to attempt 2; it does not cover a later accepted retry after the native reset. The contract and writer need an explicit accepted-reset case while retaining the captured attempt identity.

2. **Medium — Empty eligible state joins either lose counts or fail valid captures.** `wjcc_join_previous` returns at [capture-sink.inc:355](../implicit-bounded-contact-capture-attempt07/capture-sink.inc:355) whenever the previous candidate array is empty. If the next adjacent, exact-state sweep contains candidates, those rows are not counted as `new_missing`; the writer emits zero join counts. A temporary harness probe with zero candidates in generation 1 and one excluded candidate in generation 2 produced `RUN_END [0, 0, 1]`, but the reader rejected it at [capture_reader.py:472](../implicit-bounded-contact-capture-attempt07/capture_reader.py:472) because the join did not conserve the generation-2 count.

   A second empty-domain case is rejected directly by the writer. After an otherwise valid join, `capture-sink.inc:398–399` sets an error when a tie has zero same, remapped, and old-missing rows while that tie had an observed pass. A two-tie harness probe with one candidate on tie 1 and a zero-span face on tie 2 produced `map_complete = 0` and `RUN_END [0, 1, 0]`. The contract requires zero-span faces in the pass-1 census, and the reader’s conservation equations allow a tie with zero candidates on both sides. Compute missing counts from the old and new candidate totals, including empty arrays, and permit a zero/zero tie join when the census supports it.

3. **Medium — The reader accepts inconsistent post-checkconvergence attempt transitions.** The contract requires the post-checkconvergence attempt to follow the captured attempt or the source’s cutback/reset outcome. [capture_reader.py:483](../implicit-bounded-contact-capture-attempt07/capture_reader.py:483) binds the link’s captured step, increment, attempt, and iteration to `GEN_BEGIN`, but it only derives `accepted` from `icntrl` and `attempt_after`; it never validates `attempt_after` against the captured attempt. It also cannot independently check the post-iteration transition because the link record does not serialize the resulting iteration.

   I changed a nonconverged link’s `attempt_after` from 1 to 9 in a passing synthetic capture, preserving field width and the `RUN_END` byte count. `validate_capture` still returned `PASS_CAPTURE_STRUCTURE`. Validate the available attempt transition in the reader and record the post-iteration value if the reader is expected to enforce that part of the frozen contract.
