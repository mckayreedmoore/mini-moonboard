The pivot fragment is an algebraic reparameterization of the frozen attempt-02 nut-fit equations. The source `nut-coupling.inp` and `nut-coupling.json` hashes are `afd1211978cda9eb5d46bdbac5b723f2c8ada727ed2f6666c3ccedcdd58992e7` and `21c36e4f6a06f8c90cd4decbba794790d28eb88428adfdc71266b9993f694009`. I compared the source and pivot reports: all four selected shaft-node lists and rigid-fit coefficient arrays are identical. The pivot selects 24 pairwise-distinct shaft `(node, DOF)` pivots across the four fits (21 distinct shaft nodes); each six-pivot block is full rank. The dependent variables are disjoint from the controls and reserved parent actuator node. The control nodes are 116163–116170, above mesh node 116162; the actuator reservation begins at 117162. The scaled pivot condition numbers range from 4.47 to 9.97. After serialization, the equality-row-space relative error ranges from `4.99e-15` to `8.66e-15`, and the maximum residual over admissible shaft states ranges from `4.76e-13` to `1.27e-12`. This supports the report’s claim that only MPC dependency ordering changed.

The output report’s `include_file_sha256` matches the actual pivot `.inp` hash above. Its separate `artifacts["nut-coupling.inp"]` field still contains the attempt-02 source hash (`afd121…`), so that field is stale and must not be used as the pivot output identity.

This review makes no reaction, load-path, torque, strength, or capacity claim.
