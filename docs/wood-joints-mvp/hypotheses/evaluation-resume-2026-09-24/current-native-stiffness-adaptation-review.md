# Current native stiffness adaptation review

CCX 2.21's “reducing the constant stiffnesses” message in this run refers to a temporary reduction of face-to-face contact penalty laws. It does not scale the finite actuator `SPRING2` or timber material stiffness. The child input freeze binds `contact-fragment.inc` (SHA-256 `e70fc43593e8e5a5b8e445f88122fb5e675dc788207be6e6031aae9c1f71cac5`), which defines frictionless surface-to-surface contact with linear pressure-overclosure coefficient `10000`; the retry therefore uses that face-to-face normal penalty divided by 100 until the solver restores it. This is a convergence aid inside an increment retry, not a fixed-`K1e4` solve throughout every Newton attempt.

The source path is specific. In `checkconvergence.c`, failed increment retries set `kscale = kscalemax` when face-to-face mortar contact is active (lines 675–680 and 785–790; related divergence retry in `checkdivergence.c`, lines 110–115). The CCX 2.21 default `kscalemax` is 100 (`ini_cal.c`, line 322; the observed log prints 100). For linear/tied face-to-face contact, `springstiff_f2f.f` divides the normal tangent by `kscale` (line 180), and `springforc_f2f.f` divides the contact force by `kscale` (line 191). A face-to-face tangential stick slope is divided too (stiffness line 238 and force line 274), if a friction law supplies one. This case explicitly omits friction, so that tangential branch is not active. The scale is applied to the linear/tied branch; it is not evidence that all possible nonlinear or tabular contact laws are scaled identically.

The bound input manifest records a separate `200 N/mm` actuator `SPRING2` (`ordinary-finite-actuator-k1e4-attempt02/actuator-driving.json`, SHA-256 `8596a3dea5a14c7a34d9959eb940e21228d680ab5ab96a2f930ef75ce5fad4e1`). The `SPRING2` branch in `springstiff_n2f.f` assembles its element stiffness without a `kscale` argument; `springforc_n2f.f` calls `calcspringforc` without such scaling. The source search found the `kscale` arithmetic only in the face-to-face contact spring routines. Neither this retry nor the “constant stiffnesses” message means the actuator spring changed from 200 N/mm.

Restoration is part of the acceptance path. When the ordinary convergence tests would accept while `kscale > 1`, `checkconvergence.c` resets `kscale = 1` and clears `iconvergence` (lines 180–187). It must take another iteration with the original contact law. `writesta` is reached only afterward when `iconvergence == 1` and `idivergence == 0` (lines 318–320). Thus CCX does not mark an increment accepted while this temporary scale remains active. The reduced-law iterates can still supply the next Newton starting point, so convergence history may matter; acceptance establishes a converged iteration under the restored law, not immunity from path or timestep effects.

The captured attempt-02 output prefix is consistent with that logic. At increment 7 / `t = 0.0035 s`, attempt 1 reports the persistent-contact energy-residual trend, then separately reports “divergence allowed: number of contact elements stabilized,” cuts back/retries, and sets the 100 factor. Attempt 2 runs at the same increment size. Its iteration 5 logs restoration and then “no convergence”; iteration 6 converges. The copied `.sta` prefix records increment 7 attempt 2 as accepted after six iterations. The energy-residual adaptation updates the dynamic energy-residual allowance; it is not the statement that changes contact stiffness. The subsequent divergence/retry path is what activates `kscale`.

That input freeze distinguishes this child run's `artifacts_sha256.pilot.inp` (`840daddc53194bb2956d214d4e7d83cb69a21a93f3e830ab915f754ebc16791b`) from `source_lineage.source_artifacts_sha256.pilot.inp` (`48649259ba8441429a5dd094ae08487e3713d6b5b860ac39ca1acf71b837d963`), which is only the parent source deck. The log prefix also contains the start of increment 8 attempt 2 while the copied `.sta` ends with increment 8 attempt 1 marked unsuccessful, so do not use cross-file ordering there to characterize increment 8.

For interpretation, call this the nominal `K1e4` contact-input case with an observed temporary 100-fold contact softening during rejected retries and restoration before increment-7 acceptance. Do not derive an “effective physical penalty” or contact capacity from the banner: the actual local penalty is the input coefficient combined with CCX's active face-to-face contact formulation and area/discretization, and the failed reduced-stiffness iterates are not fixed-`K1e4` responses. Keep the input coefficient, adaptive retry history, restored accepted iteration, and any penetration/contact-force output distinct. This solver behavior does not itself pass a mechanics criterion.
