# Finite-actuator angular-momentum audit: source-bound readiness

## Disposition

The immutable five-state prefix does not contain enough information for an
exact or bounded current-position angular-momentum closure. The earlier
linear-momentum result is unchanged. Do not report angular closure from the
slave-side `CF` moments alone.

The bounded first target is the cleat subassembly through the four accepted
states with complete contact triplets, `t <= 0.002 s`. The pinned contact

absent, so that endpoint is excluded from a cleat contact-moment balance.
The global `CDIS`/`CSTR` counts through 0.0025 s do not repair those pair

## Contact torque missing from `CF`

CalculiX 2.21 `printoutcontact.f` evaluates each slave integration-point
location with current coordinates `co+vold` (lines 104–108, 135–142), forms
the contact force `df`, and accumulates `coords × df` (175–205). It reports
that slave resultant and moment about the origin (225–228). In
`springforc_f2f.f`, the equal-and-opposite master force is distributed using
master shape weights at `pproj` (424–438); the force location is therefore
the current interpolated master point, not the slave point. For one contact
pair, with `r_slave` and `r_master` the current slave and master integration-point
positions:

```text
M_slave = sum(r_slave x df)
M_master = sum(r_master x (-df)) = -M_slave + C_pair
C_pair = sum((r_slave - r_master) x df)
```

The correction `C_pair` vanishes only when every force is collinear with the
current slave-to-master separation. This deck uses frictionless face-to-face
penalty contact (`contact-fragment.inc` says `*FRICTION` is omitted). Source
`gencontelem_f2f.f` initializes master projection coordinates and normals,
then reuses them after the initial pass (lines 490–508, 520–547).
`springforc_f2f.f` evaluates the current separation against that stored
projection and normal (120–157) and applies the force along the stored normal
(248–253). Finite tangential motion can therefore leave a force-line offset;
the source does not establish `C_pair = 0` at the converged state.

For the cleat, pairs 1 and 2 are slave-side wood interfaces and use their
reported `CF` moments directly. The eight cleat-as-master pairs are WJCP_005,
009, 013, 017 (head-washer/first-receiver interfaces) and WJCP_020, 022, 024,
026 (shaft-to-wood-bore interfaces). For each, the cleat-side moment is
`-M_CF + C_pair`, not `-M_CF`. The four bore pairs have zero reported `CF` vector
and zero reported area in the observed complete rows. Preserve those as
reported zeros only; neither these values nor the one incomplete final bore
row prove a physical zero-force bound.

No current output gives a defensible bound on `C_pair`. The input requests
`CDIS,CSTR` (`pilot.inp`, lines 406–408), but `*FRICTION` is absent. The
2.21 manual says the tangential `CDIS` components are calculated only when a
friction coefficient is defined (manual extract lines 19895–19911; SHA-256
`118fc7e79e1961b713e4cd3c7cf653cf15f92b137b476ad4db3e47e405883f39`). Thus
those saved fields do not supply a tangential-offset bound. `CSTR` pressure
and total `CF` area are not paired point-by-point with the force-line offsets;
their aggregate values cannot bound the cross-product sum without that
missing offset information.

The existing `.cel` history is not a recoverable alternative. In
`gencontelem_f2f.f`, the `CONTACT ELEMENTS` writer labels blocks by
step/increment/attempt/iteration (111–145); its internal contact-element
connectivity also carries Gauss/surface indices (705–715), but the serialized
`.cel` records contain only generated C3D8/C3D6 node connectivity (722–763).
It writes no projection coordinates, current master quadrature points,
contact forces, or stresses. The parent checked only the first `.cel`
records and found this same connectivity format; reading the multi-gigabyte
history cannot supply the missing wrench term.

## Constraint torque distinction

The four rigid-carrier `*RIGID BODY` definitions are generated by
`rigidbodys.f` and initially seeded by `rigidmpc.f`, but CCX 2.21 updates
`RIGID` rows in `nonlinmpc.f` from the current rotation-vector state on each
nonlinear iteration (`nonlingeo.c` calls it at lines 2353–2357;
`nonlinmpc.f` lines 79–194). Do not classify these native rigid-carrier MPCs
as fixed-coefficient equations. Their reaction forces are still not
available in this run's `RF` output.

Separately, `nut-coupling.inp` authors 24 ordinary fixed-coefficient
`*EQUATION` rows, six per nut; its header explicitly says the rotation
controls encode infinitesimal theta. These are not the generated `RIGID`
rows and have no corresponding nonlinear update in the pinned source. A
current-position torque audit cannot infer their reaction couple from
`RF`: the 2.21 manual states that forces induced by MPCs are not calculated
for `RF` (extract lines 24584–24592). Their row multipliers or equivalent
constraint-reaction wrench are missing. This is a separate whole-model
closure gap from the contact offset term.

## Minimal next evidence

For the cleat contact term, a small output-only source instrumentation is
sufficient; no full point dump is needed. In `printoutcontact.f`, use the
existing pair membership, `pmastsurf(1:2,igauss)`, current `co+vold`, and the
same master face shape routine/weights as `springforc_f2f.f` to evaluate
current `r_master` for each point. Accumulate and print the master-side
`(-F_slave, M_master)` about the global origin per requested pair, alongside
the existing slave `CF`; print `C_pair = M_slave + M_master` as a review aid.
Source inspection confirms this can use the same stored projection parameters
and force weights as assembly, so it avoids a large per-point result file.
Before using it, validate force sign and precision on a flat, aligned contact
fixture and a deliberately tangentially offset contact fixture.

The ordinary `*EQUATION` nut-fit contribution still needs its work-conjugate
reaction wrench to be captured at the constraint elimination/recovery point
or independently shown to conserve current-position moment. A plain `RF`
request is insufficient. Keep this question separate from the source-verified
nonlinear rigid-carrier update and from the contact-only instrumentation.
Use the existing source/output precision bounds when interpreting any later
residual; do not add an arbitrary tolerance or claim a pass from the present
prefix. The output-only implementation sketch, including its conditional
normal-spring-energy diagnostic and limits, is documented in the
[printoutcontact patch README](printoutcontact-master-wrench.README.md) and
[patch file](printoutcontact-master-wrench.patch). Neither artifact has been
applied to the pinned source or run.
