# Implicit contact-switch observability review, attempt 01

## Decision scope

The frozen attempt04 replay cannot tell whether its contact-count-only stall is a near-zero classification flicker or a meaningful force change. Its 44 completed CVG rows show the residual, displacement, and viscoelastic gates passing; 41 rows fail only `contact_change_gate_clear`. There is no per-point signed-gap or rejected-iterate force record. Keep `delcon=0.001` and the contact law unchanged. This review selects no convergence relaxation and does not interpret a numerical stall as physical failure.

A next-iteration generator pass can, conditionally, expose the preceding rejected iterate’s post-correction geometry. In pinned `nonlingeo.c`, contact regeneration precedes `nonlinmpc` (2317–2327 before 2369–2373); after the solve, `vold` is copied from corrected `v` at 3300, then checked for convergence at 3440–3455. For this dynamic path (`nmethod=4`), the static surface-contact line search is excluded at 3213, and the caller restores `vold=vini` on cutback at 3531–3533. Thus a same-increment, non-cutback iteration’s next generator ordinarily evaluates the prior corrected displacement before the next MPC update. Treat that as a candidate join, not a proven trace: an output-only snapshot of `vold` after the correction and at the next generator entry must match exactly (or within an explicitly fixed serialization tolerance), with unchanged increment and cached contact mapping. Reject the join on any mismatch, cutback, accepted terminal state, increment transition, or remap. The existing replay does not contain this snapshot, so no historical rows can be retroactively joined.

## Minimal output-only observation

For a future authorized diagnostic build, retain the frozen solver inputs and add diagnostics only:

1. In `gencontelem_f2f.f`, at each mapped integration point, log a stable key (step, increment, iteration, tie/pair, slave-face index, `igauss`, cached master face), signed `clear`, mapping-valid flag, and final generated/not-generated result after all classification rules. This records the exact set used for the count gate. If a master mapping is absent, report it as unmapped; do not invent a gap.
2. In `resultsmech.f`, before its per-iteration arrays are freed, log actual generated-spring `clear` (`stx(1)`), signed normal pressure (`stx(4)`), area, pair key, normal resultant, and spring energy when enabled. This is the corrected-state force on the set generated before the solve. Preserve signs: `springforc_f2f.f:186–201, 248–253` uses `stiff=-area*K*clear/kscale` and does not clamp a retained spring with positive clearance; such a stale spring can therefore have a signed tensile trial force. Never replace this with `max(0, pressure)`. The frozen contact definition has no friction, so it supplies no shear-force/slip observation; log zero/unsupported explicitly rather than implying measured shear behavior.
3. In `nonlingeo.c`, keep a diagnostic-only copy of corrected `vold`; compare it at the next generator entry before `nonlinmpc`. Tag that entry’s gap/set rows as the prior iterate’s post-correction state only if the snapshot, increment, and mapping checks pass. Omit accepted-terminal and cutback transitions. This separates the force actually assembled on the old set from the set the same corrected geometry would generate.

This first pass identifies switched point IDs and margins and measures actual assembled active-spring pair resultants/energy. It does **not** alone bound omitted force: a newly penetrating point may have no spring in the just-completed solve, so `resultsmech` has no actual `stx` for it. If a force/work decision is required, add a second, read-only candidate-law reconstruction for all mapped points at the verified state, explicitly marked “not assembled”; compare its signed point forces and pair sums with the actual `stx` set. For this frictionless linear law, validate the source-equivalent force and energy algebra against `springforc_f2f.f`; do not silently apply unilateral clamping to actual stale-spring records. A conservative absolute correction-work bound also needs the point/nodal force difference and the same iteration’s displacement correction (or a proven bound using its nodal distribution). It is not available from the present aggregate CVG/CEL records. A declared quantitative “material” threshold would still be needed to classify the resulting measurements.

Cap any future full-run trace: first qualify the logging on a small known-answer coupon; emit aggregate per-pair summaries every iteration and detailed records only for switched points, with a fixed output-size limit and fail-closed overflow. Attempt04’s initial active count is 93,540 springs, so an unbounded row-per-point-per-iteration dump is not an acceptable default. No source patch, build, native run, parameter change, or physics change is authorized by this review.

## Small known-answer validation required before use

Use a tiny flat frictionless face-to-face linear-penalty model with known mapped points and prescribed normal states: one penetrated point, one exactly touching point, and one positive-clearance point. Check signed gap, stable point/pair keys, the generator’s strict positive-clearance exclusion, signed pressure/resultant, and `CELS`/spring energy against hand values and accepted-state `*CONTACT PRINT` where applicable. Include one point that becomes open after generation to prove the diagnostic preserves the source’s signed tensile stale-spring result instead of clipping it. Verify logging leaves deck, generated set, solver gate history, and numerical output unchanged apart from diagnostic records. Separately test snapshot mismatch, cutback, missing master mapping, and trace-size overflow; each must invalidate the join or report incomplete capture. No such validation has been run.
