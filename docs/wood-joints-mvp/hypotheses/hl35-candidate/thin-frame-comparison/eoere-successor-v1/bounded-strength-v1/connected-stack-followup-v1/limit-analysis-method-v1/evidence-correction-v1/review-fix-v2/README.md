# Bounded review corrections, version 2

This fixes three confirmed evidence defects in the preserved
[first correction](../README.md). It reuses that producer/verifier and the
[original synthetic mechanics](../../README.md). All six original method
files, five first-correction files, issued attempts and reviews remain frozen.
No candidate actions, geometry, material qualifications or joint capacities
are introduced.

## Raw load and numerical repair

Review showed that a reported raw load could be multiplied by a million while
dividing its numerical scale by a million, preserving an otherwise valid
scaled field. [body.py](body.py) now reconstructs the raw density by dividing
the recorded density by the claimed scale. It checks raw bearing, member-force
equilibrium, complete shaft first moment and every raw moment extremum against
the frozen normalized tolerances. The original prefix integrator is reused
for the raw moment extrema; the retained dimensional checker separately
checks the repaired field.

The repair itself must satisfy a necessary bound derived from the original
algorithm. With `epsilon = 1e-8` (LP certificate tolerance),
`delta = 2e-9` (moment-cut tolerance), `m = 2e-12` (numerical margin),
`F0 = min(qs Ls, qm Lm)` and `cap = My / (F0 T)`:

```text
minimum numerical scale = (1-m) min(1/(1+epsilon), cap/(cap+delta))
raw load <= F0 (1+2 epsilon+m)
```

The implementation allows the recorded numerical margin in its comparisons.
It also checks the reconstructed raw fields directly. These are numerical
feasibility bounds, not engineering adjustment factors or allowable loads.
Coordinated million-fold and 0.1% raw-load/scale forgeries are rejected, even
when run/replay bytes and updated provenance hashes agree.

## Executed source and evidence paths

The supported entrypoint is the small [run.py launcher](run.py). It reads the
body once, records that buffer's digest and compiles that exact buffer. The
body requires this injected loaded-source binding and rejects a later file
change. The launcher captures its own source view during initialization and
checks it before loading the body. The body also executes the captured v1
correction bytes authenticated by its frozen five-file map. Editing the
launcher, body or loaded v1 correction before the first source snapshot
rejects the run; the loaded code cannot be attributed to the later bytes.

Verification rejects symlinks in run/replay files or any path component.
It retains the original absolute lexical paths, file and ancestor identities,
and consumed hashes. These are checked again through final receipt
serialization. Replacing an ordinary evidence directory with an identical
copy is also detected. This policy applies to both the CLI and the reused
verifier function, including `--run=...` argument syntax.

The existing finite schemas, exact synthetic/null-capacity claims, independent
48-digit analytical-mode checks, field integration, source checks and exclusive
output creation remain in use. The production/verification formats are reused
with the expanded **26-file source closure**. Old receipts retain their own
original closure and are not substituted for v2 production markers.

## Targeted regression results

[check.py](check.py) exercises the actual CLI and isolated copied-source
processes. [Verification](verification.json) binds the recorded commands and
outputs. Two fresh production invocations and verification pass. All three
production files replay byte-for-byte; the numerical result and 45 bearing
fields also match their original issued bytes.

Fourteen negative controls reject without a successful receipt or production:

- Two coordinated raw-load/scale forgeries, preserving the valid scaled field.
- Three loaded-source changes before first use: launcher, body and v1 correction.
- Three symlink evidence forms: run directory, ancestor directory and files.
- Two path replacements during receipt serialization: a symlink and an
  ordinary replacement directory with identical bytes.
- Four retained compact-result failures generated by the frozen v1 helper:
  candidate capacity, invented analytic load, nonfinite peak and duplicate case.

The independent member-force and end-moment residuals remain `9.10e-13 lbf`
and `3.39e-12 lbf·in`. The original 128-cell analytical shortfall remains
**0.005209%**. No new solver model or candidate result follows from these tests.
The preceding limits on scalar ideal-plastic behavior, mode-specific design
reduction, compatibility, vector interaction, axial behavior, group action,
splitting and complete joint resistance remain.

## Reproduction and retention

Run from the repository root with fresh output names. Invoke the launcher;
direct body execution is deliberately rejected.

```bash
review_fix=docs/wood-joints-mvp/hypotheses/hl35-candidate/thin-frame-comparison/eoere-successor-v1/bounded-strength-v1/connected-stack-followup-v1/limit-analysis-method-v1/evidence-correction-v1/review-fix-v2
review_raw=fea/generated/thin-bolted-current-contact-v1/eoere-successor-v1/bounded-strength-v1/connected-stack-followup-v1/limit-analysis-method-v1/evidence-correction-v1/review-fix-v2
uv run python -B "$review_fix/run.py" produce --out "$review_raw/reproduce-01"
uv run python -B "$review_fix/run.py" produce --out "$review_raw/reproduce-02"
uv run python -B "$review_fix/run.py" verify --run "$review_raw/reproduce-01" --replay "$review_raw/reproduce-02" --out "$review_raw/reproduce-verification.json"
uv run python -B "$review_fix/check.py" regress --out "$review_raw/reproduce-controls"
```

[Inputs](inputs.json) embed the frozen v1 source map and pin its three review
receipts. Issued v2 evidence is in ignored `attempt02`; `attempt01` retains
the successful exploratory run and source before lint cleanup. All copied
fixtures and rejected evidence remain recoverable. The active method entrypoint
is this guarded launcher, subject to the main session's independent review.
The earlier method/correction files remain historical evidence. No archive,
prune, shared-document edit, staging, CAD or frame solve occurred. Permanent
files contain source, pins and compact verification rather than duplicate
numerical fields. Shared integration and publication remain with the main session.
